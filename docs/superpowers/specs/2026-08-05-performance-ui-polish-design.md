# 股票提醒助手 v2.0.0 性能修复与 UI 质感升级设计

**日期：** 2026-08-05

**状态：** 已批准

**目标版本：** v2.0.0
**范围：** Popup 性能架构、完整视觉系统、列表/网格、顶部操作、列设置、行操作、对话框及全状态体验

## 1. 背景

当前分支 `feature/v2.0.0-foundation-rebuild` 已通过类型、Lint、架构、构建、契约、单元、组件、覆盖率、无障碍、回滚、确定性构建、依赖审计和扩展打包检查。发布验收仍有一个稳定阻塞项：20 个分组、500 只股票场景下，视图切换 DOM 更新 p95 连续四次测得 136.6–142.2ms，高于 100ms 发布门槛。

现有 Popup 也存在一组相互关联的视觉问题：顶部操作与标题争抢空间、工具栏易换行、列表列数过多、行内操作噪声高、对话框呈现偏窄、组件之间的间距与层级不统一。性能修复和视觉调整必须共同设计，避免以高成本模糊、阴影或全量 DOM 换取短期观感。

## 2. 已批准的产品决策

1. 采用“精密终端”视觉方向：克制、专业、耐看，依靠边界、色阶、留白和数字秩序形成质感。
2. 保留列表与网格两种视图。
3. 优化范围覆盖整个 Popup，而非只修改行情看板。
4. 顶部操作必须保留图标和文字说明：浅色/深色、价格、多选、添加。
5. 性能采用“可复用虚拟化 + 活跃视图按需挂载”，不采用仅靠 `content-visibility` 或分批补绘的折中方案。
6. 不考虑保留现有呈现实现的兼容成本；保留的是用户数据、业务语义、架构边界和回滚契约。
7. 列设置属于纯展示偏好，不进入业务 `BoardConfig`；与主题一样由 Popup Store 管理并持久化到经校验的 `localStorage`。

## 3. 目标与非目标

### 3.1 目标

- 500 股票视图切换 DOM 更新 p95 不超过 80ms，为 100ms 发布门槛保留至少 20ms 余量。
- Bootstrap p95 不超过 200ms。
- DOM 节点数量由视口决定，不随 500 股票线性增长。
- 行情更新只修改当前可见且值发生变化的节点。
- Popup 固定为 420×560，主行情区连续占用 390px，顶部和底部不产生布局跳动。
- 完整统一顶部、分组、工具栏、列表、网格、对话框、菜单、加载、空、错误、缓存和缺失状态。
- 保持键盘、屏幕阅读器、缩放、对比度、触控目标和 reduced-motion 门禁。
- 完整通过 `npm run release:verify`。

### 3.2 非目标

- 不修改 Domain 行情语义、Provider、缓存、退避或调度策略。
- 不修改 RPC v2 方法、StorageCoordinator、schema v2 或 revision 算法。
- 不新增运行时第三方依赖、网络字体或图标字体。
- 不新增通知、提醒或其他业务功能。
- 不通过降低容量、放宽性能阈值或改变测量方式解决性能失败。

## 4. 性能架构

### 4.1 `VirtualWindow` 纯计算核心

新增 Popup 内部纯函数模块，输入：

- `itemCount`
- `itemExtent`
- `viewportExtent`
- `scrollOffset`
- `overscan`

输出：

- `startIndex`
- `endIndex`（左闭右开）
- `beforeExtent`
- `afterExtent`
- 规范化后的 `scrollOffset`

该模块不依赖 DOM、Store 或 Chrome API，可独立覆盖空列表、首尾边界、越界滚动、数据增删和 overscan 行为。

### 4.2 列表虚拟化

- 保留真实 `<table>`、`<thead>` 和 `<tbody>`。
- `<tbody>` 仅挂载当前窗口内的真实股票行，前后各使用一个 `aria-hidden` 占位行维持总滚动高度。
- 表格设置 `aria-rowcount`，每个真实行设置 `aria-rowindex`，屏幕阅读器能够理解总数量和当前位置。
- 固定行高 48px；默认 overscan 为上下各一个视口，实际节点上限由视口与 overscan 决定。
- 可见行继续使用 keyed 更新；重复赋值前比较文本、class 和 ARIA 状态，只修改实际变化字段。

### 4.3 网格虚拟化

- 两列网格按“行”计算虚拟窗口，每个虚拟项代表一整行卡片。
- 使用容器上下 padding 维持滚动高度，不创建不可见卡片。
- 固定卡片行高，避免运行时测量造成布局回流。
- 卡片节点保持股票代码 key；切换排序时复用仍处于窗口内的节点。

### 4.4 活跃视图按需挂载

- `stock-board` 首次只创建当前视图。
- 另一视图首次进入时才创建；离开后停止接收 ViewModel 更新并保存独立滚动位置。
- 非活跃视图最多保留已虚拟化的小型节点窗口，不保留 500 个节点。
- 返回某个视图时恢复其滚动位置；数据量缩小时先规范化滚动位置再渲染。

### 4.5 事件调度与容错

- 滚动事件使用单个 `requestAnimationFrame` 合并；同一帧多次滚动只计算和渲染一次。
- `ResizeObserver` 只更新视口尺寸与虚拟窗口；不可用时回退到 390px 视口。
- 虚拟窗口输入异常时回退到安全首屏区间，不能触发 Popup 白屏。
- 组件断开连接时取消未执行的 animation frame 和 observer。
- 焦点目标不在当前窗口时，先滚动目标进入窗口，完成渲染后再聚焦。

## 5. UI 视觉系统

### 5.1 整体结构

Popup 固定 420×560：

| 区域 | 高度 | 说明 |
|------|------|------|
| Header | 52px | 身份区 + 四个图标文字按钮 |
| Group Tabs | 38px | 分组横向导航 |
| Toolbar | 48px | 搜索、排序、列表/网格、更多 |
| Board | 390px | 唯一纵向滚动区 |
| Status Bar | 32px | 实时/缓存/缺失计数与刷新 |

总高度严格为 560px。`body`、`stock-app` 和顶层布局不得产生纵向滚动；Board 是唯一纵向滚动容器。

### 5.2 精密终端风格

- 深色仍为默认主题，浅色主题保留。
- 使用低层级背景、表面、提升表面三档色阶，边界使用 1px 低对比度线。
- 除菜单、对话框和 Popup 外框外，不使用逐行或逐卡片阴影。
- 禁止 `backdrop-filter`、大面积透明叠层和高成本模糊。
- 数字使用系统字体的 `tabular-nums`；文本继续使用系统中文字体栈。
- 红涨绿跌保持 A 股语义，并用正负号/文字状态避免只靠颜色表达。

### 5.3 顶部操作

四个按钮均为 44px 高，并同时展示图标与短文字：

1. `浅色` / `深色`
2. `价格`
3. `多选`
4. `添加`

“添加”使用品牌色填充。价格隐藏、多选和当前主题使用 `aria-pressed`、描边与背景三重反馈。图标使用内联 SVG，文字不得在 420px 宽度下截断。

### 5.4 分组与工具栏

- 分组标签单行横向滚动，不显示无语义的左右箭头。
- 当前分组通过文字颜色、字重和底部指示线共同表达。
- 工具栏固定单行：弹性搜索框、98px 排序、76px 视图分段控件、38px 更多按钮。
- 列设置进入更多菜单并完成接线，不保留无响应按钮。

### 5.5 列表

默认展示四项核心行情和一项操作：

- 股票：名称 + 代码/市场/行情状态副标题
- 现价
- 涨跌幅
- 成交额
- 行尾菜单

置顶股票使用左侧 3px 金色边界及极弱背景，不使用整行高亮。行尾菜单承载置顶、移动和移除，避免主表持续显示图钉与上下箭头。

列设置允许切换成交额、代码、状态等可选信息，但股票、现价和涨跌为不可全部关闭的核心信息。列配置是全局 Popup 展示偏好：Store 的 view slice 是运行时唯一真相，持久化使用版本化 key `uiColumns:v1`。读取时必须校验、去重、补齐未知版本的默认值；损坏数据回退为默认四列。它不进入 `BoardConfig`、RPC 或 `userDataRevision`。

### 5.6 网格

- 两列卡片，信息层级为名称/代码、价格、涨跌幅、成交额和状态。
- 操作同样进入卡片行尾菜单。
- 卡片使用 1px 边界与表面色差，不使用重阴影或模糊。
- 置顶卡片使用金色边界标记，并保留非颜色提示。

### 5.7 对话框和菜单

- 对话框居中显示，最大宽度 360px，最大高度不超过 Popup 可视区。
- 搜索结果、表单字段、选项组、错误提示和操作按钮使用统一 8/12/16px 间距节奏。
- 行尾菜单锚定触发元素；点击外部或按 Escape 关闭并恢复焦点。
- 危险操作使用明确文案、危险色和确认步骤。
- 所有 overlay 使用同一焦点陷阱、返回焦点和滚动锁定规则。

## 6. 状态与动效

### 6.1 状态

- Loading：六行无数字骨架，不显示模拟行情。
- Empty：说明当前分组为空，并提供“添加股票”主操作。
- Recoverable Error：保留已有数据，显示错误说明和重试入口。
- Fatal Error：仅 bootstrap 无法恢复时显示静态 fallback。
- Cached：显示缓存时间或明确缓存标签。
- Missing：显示“暂无行情”和 `--`，绝不生成价格。

### 6.2 动效

- 价格变化高亮 180ms。
- 主题颜色过渡 120ms。
- 菜单和对话框淡入 120ms。
- 滚动、排序和虚拟窗口切换不使用位移动画。
- `prefers-reduced-motion: reduce` 下所有动画和过渡归零。

## 7. 数据流与架构边界

单向数据流保持为：

```text
Store → selectors → BoardViewModel → active virtual view → visible keyed nodes
```

- 滚动位置、视口尺寸和虚拟区间属于组件本地状态，不进入 Store。
- 视图模式、排序和业务操作继续通过语义事件进入 Store/CommandController。
- 列设置通过独立语义事件进入 Store view slice，并由 AppShell 同步到 `uiColumns:v1`；组件不得直接访问 `localStorage`。
- 组件不直接访问 RPC、Repository 或 Chrome Storage。
- 主题继续使用 Popup `localStorage`，不进入业务数据 revision。
- Domain、Application、Infrastructure、Protocol 分层和依赖方向不变。

## 8. 测试策略

所有实现按测试驱动推进，先观察失败，再写最小实现，通过后重构。

### 8.1 单元测试

- `VirtualWindow`：空数据、正常窗口、首尾 overscan、负滚动、超大滚动、数据缩减、不同视口和网格行数。
- 可见节点 diff：相同 ViewModel 不写 DOM，价格/状态变化只改目标字段。
- 滚动调度：同帧多次事件只执行一次更新，断开连接后不执行。

### 8.2 组件测试

- 500 股票下列表真实股票行保持在配置上限内。
- 500 股票下网格卡片数量保持在配置上限内。
- 非活跃视图不接收 ViewModel 更新。
- 列表/网格切换恢复各自滚动位置。
- 虚拟窗口滚动、排序、数据减少和焦点恢复正确。
- 顶部四按钮保留图标与文字，并具有正确 `aria-pressed`。
- 列设置、行尾菜单、空状态 CTA、错误重试和居中对话框完整接线。
- 列设置损坏值、重复值、未知列和未知版本全部回退或规范化为安全默认值。

### 8.3 E2E 与无障碍

- 列表和网格在 500 股票下快速切换、滚动、排序和刷新。
- 键盘可从分组、工具栏进入虚拟列表，并定位到窗口外股票。
- 行尾菜单和对话框支持 Tab、Enter、Space、Escape 和焦点恢复。
- 深色/浅色、空/错误/缓存/缺失、缩放 90–150% 和 reduced-motion 状态继续通过 axe 与现有手工断言。
- 实时网络行情场景保留，但发布判定必须区分外部数据源瞬时失败与可复现产品失败。

### 8.4 性能与发布

- 500 股票视图切换 DOM 更新 p95 ≤80ms。
- Bootstrap p95 ≤200ms。
- 虚拟滚动单次更新不得产生超过 50ms 的长任务。
- 测试断言列表和网格 DOM 节点数量上限，防止未来回退到全量渲染。
- 最终完整运行 `npm run release:verify`，包含 CI、性能、审计、回滚、确定性构建、商店截图、打包和包体检查。

## 9. 实施边界

预计改动集中在：

- `src/popup/components/`：虚拟化核心、Board、Table、Grid、Card、Header、Toolbar、菜单、列设置、对话框。
- `src/popup/store/` 与 `src/popup/view-models.ts`：完成列设置的 view 状态、规范化和必要的展示投影；不引入滚动状态或业务 schema 字段。
- `extension/popup/styles/`：精密终端 tokens、固定布局、组件与无障碍样式。
- `tests/unit/`、`tests/component/`、`tests/e2e/`：虚拟化、完整交互、视觉结构、无障碍和性能回归。
- `store-assets/`：仅在最终发布验证阶段刷新。

不得改动业务 schema、RPC 契约和行情来源，除非实施过程中发现现有实现违反本设计且先获得新的设计批准。

## 10. 完成标准

同时满足以下条件才算完成：

1. 500 股票性能门禁稳定通过，至少连续三次 `npm run test:performance` 全绿。
2. 完整 `npm run release:verify` 全绿。
3. 列表与网格真实节点数量有明确上限，并有自动化回归测试。
4. 顶部按钮保留图标与文字；全部 Popup 状态使用统一精密终端视觉语言。
5. 列设置和行操作不存在无响应或半接线入口。
6. 现有存储、RPC、行情、回滚、权限和无模拟价格不变量全部保持。
7. 工作区只包含本次明确范围内的已跟踪改动，发布 ZIP 可确定性复现。
