## 1. 结论摘要

**可行，且零权限新增。** 两个现有数据源（东财主源 / 腾讯备源）的现有接口
对大盘指数开箱即用，manifest 的 host_permissions 无需任何改动：

| 数据源 | 接口 | 指数支持 | 请求格式差异 |
|---|---|---|---|
| 东财主源 | `push2.eastmoney.com/api/qt/ulist.np/get` | ✅ 8/8 指数正常 | 无——secid 规则：沪指数 `1.000xxx`、深指数 `0.399xxx`、北证50 `0.899050`，**与股票可混合同批** |
| 腾讯备源 | `qt.gtimg.cn/q=` | ✅ 8/8 指数正常 | 无——代码直接带前缀：`sh000001` / `sz399001` / `bj899050` |
| 东财搜索 | `searchapi.eastmoney.com/api/suggest/get` | ⚠️ 能搜到但被过滤 | 指数 `SecurityType=5`，被现有白名单 `{'1','2','25','27'}` 拒掉 |

实测通过的 8 个指数：上证指数(sh000001)、深证成指(sz399001)、创业板指(sz399006)、
沪深300(sh000300)、科创50(sh000688)、上证50(sh000016)、中证500(sh000905)、北证50(bj899050)。

## 2. 实证记录（真实接口响应摘要）

### 2.1 东财批量接口（指数 + 股票混合同批 ✅）

`secids=1.600519,1.000001,0.399001,0.000001` 同批返回：

```
f13=1 f12=600519 贵州茅台  现价=1311.02
f13=1 f12=000001 上证指数  现价=3901.33   ← sh000001
f13=0 f12=399001 深证成指  现价=13769.35
f13=0 f12=000001 平安银行  现价=11.68     ← sz000001
```

关键事实：
- **f13（市场）对指数的语义与股票一致**（1=沪 / 0=深 / 0+8开头=北交所），
  `parseEastmoney` 现有前缀推断 `f13===1?'sh':/^[489]\d{5}$/.test(code)?'bj':'sz'`
  对 8 个指数全部推导正确，**解析器零改动即可产出正确的规范化代码**。
- `sh000001`（上证指数）与 `sz000001`（平安银行）在响应中靠 f13 区分，无歧义。
- 指数的价格/涨跌幅/涨跌额/昨收/开高低/成交额均为真实有效值。

### 2.2 腾讯备源

`q=sh000001,sz399001,sz399006,sh000300,sh000688,sh000016,sh000905,bj899050`
全部返回（88 字段；北证50 为 87 字段，>6 的哨兵阈值，解析无碍）。
名称/现价/昨收/涨跌额/涨跌幅/开高低全部正确；响应键自带前缀，`parseTencent` 现有
正则直接可用。

### 2.3 东财搜索接口

| 查询 | 命中形态 |
|---|---|
| `上证指数` / `szzs` | `Code=000001 SecurityType=5 Classify=Index MktNum=1` |
| `399001` | `Code=399001 SecurityType=5 Classify=Index MktNum=0` |
| `899050` / `北证50` | `Code=899050 SecurityType=5 Classify=34 MktNum=0` ⚠️ |

搜索能搜到指数，但注意三点：
1. `SecurityType=5` 不在现有白名单 `{'1','2','25','27'}` 内——若要支持「搜索添加指数」需扩白名单；
2. **北证50 的 `Classify` 是 `34` 而非 `'Index'`**、且 `MktNum=0`——搜索端前缀不能只按 MktNum 映射，8 开头代码需归 `bj`（与行情端 parseEastmoney 的规则对齐）；
3. 放行 `SecurityType=5` 会带入大量非大盘指数（如 `980073 生猪指数`），需要白名单约束或全量放开的产品决策。

## 3. 风险清单（字段含义随品种/源变化——f51/f52 教训的延续）

**这是本次调研最重要的发现：指数和股票用同一套字段，但部分字段对指数是无意义的
哨兵值，直接复用现有解析/展示会把假数据当真值。**

| # | 坑 | 实测证据 | 后果（若不处理） |
|---|---|---|---|
| R1 | 东财指数 PE/PB 上报 `0` | 上证指数 `f9=0 f23=0` | `num(0)=0` 不是 null，`enrichQuote` 会保留 `pe:0/pb:0` → 展示 `0.00` 而非 `--` |
| R2 | 腾讯指数涨跌停上报 `-1` | `sh000001 [47]=-1 [48]=-1` | `parseTencent` 会存入 `limitUp:-1` → 渲染 `-1.00` |
| R3 | 腾讯指数 PE 与东财口径不一致 | 腾讯 `PE=17.70 PB=0.00` vs 东财 `f9=0` | 同一指数两源展示不同的假值 |
| R4 | 北证50 搜索形态例外 | `Classify=34 MktNum=0` | 搜索前缀误推 `sz899050`，行情请求 404/空 |
| R5 | `normalizeStockCode` 无法表达指数代码 | `sh000001`：显式 `sh` 与推断 `sz` 冲突 → null；`399001`：不在股票段表 → null | 指数代码过不了 protocol 校验器、进不了 watchlist（见 §4 方案取舍） |

处理原则（与 f51/f52 一致）：**指数场景在 domain 层定义独立的值对象/投影，从源头
剔除无意义字段**（PE/PB/换手/涨跌停），而不是在展示层逐个打补丁。

## 4. 方案对比

### 方案 A：固定指数条（推荐第一期）

popup 顶部（header 与 toolbar 之间）常驻一条指数栏，默认显示 上证指数 / 深证成指 /
创业板指（硬编码目录，不可增删）。

- **产品语义**：大盘是大盘、自选是自选，符合主流行情 App 形态
- **零 schema 改动**：不动 `UserData`/`BoardConfig`/`sanitize-v2`，无迁移风险
- **零代码体系冲突**：指数代码用独立的 `IndexCode` 品牌 + 硬编码目录，
  完全绕开 `normalizeStockCode` 的 R5 冲突
- **天然规避 R1-R4**：指数条只展示 名称/点位/涨跌幅（红涨绿跌），
  从 domain 投影层就不带 PE/PB/换手/涨跌停
- 改动集中：domain 新增 index 目录与投影 + protocol 注册表扩展 + SW 编排并入 +
  popup 一个新组件

### 方案 B：指数进自选（可作第二期）

用户搜索并添加任意指数到 watchlist，进分组/排序/批量体系。

- 需要扩展 `normalizeStockCode`（指数段规则：显式 `sh`+`000xxx` 合法、
  `399xxx` 归深、`899xxx` 归北）+ brands + sanitize-v2 + validators 全链
- 搜索端需扩 `SecurityType=5` 白名单并处理北证50 例外（R4）
- watchlist 变成混合品种：分组、批量工具栏、排序（price/change 对指数语义不同）、
  可配置列（5 列里 PE/换手对指数无效）、详情 tooltip 全部要适配
- 存储 schema v2 的 watchlist 语义变化 → sanitize/migration/E2E 全链回归

### 方案 C：A + B（最终形态）

固定条 + 可搜索添加，建议分两期：先 A 验证数据链路与 UI 形态，B 作为独立迭代。

## 5. 方案 A 改动面清单（按架构分层）

| 层 | 文件 | 改动 |
|---|---|---|
| Domain | `src/domain/index-quote.ts`（新） | `INDEX_CATALOG`（3-8 个大盘指数的 IndexCode/名称/市场映射唯一真相）+ `IndexQuote` 值对象（name/price/changePercent/change/amount，不含 PE/PB/涨跌停）+ `toIndexQuote(quote)` 投影纯函数 |
| Protocol | `src/protocol/registry.ts` + `messages.ts` | `BootstrapResult` 增加 `indexQuotes` 字段；或 `quote:refresh` payload 增加 `indexCodes`——**单一注册表两端口同步**（registry + rpc-handlers），payload 用内联 validator |
| Application | `src/application/quotes/quote-service.ts` 或新 `IndexQuoteService` | 指数代码并入 refresh 请求集合（实测混合同批可行，东财 1 次请求搞定）。⚠️ 注意「空自选股不请求网络也不改变退避状态」不变量的表述需收窄为「自选股为空」——指数常驻意味着 watchlist 空时仍会有指数请求；若不希望指数失败污染自选股退避状态，指数走独立轻量路径 |
| Infrastructure | 东财 `toSecids` | 已天然支持（`sh→1.` `sz/bj→0.`），指数代码自动正确——**零改动**（写单测锁死） |
| | `provider-parsers.ts` | `parseTencent` 的 `limitUp/limitDown <= 0` 过滤（R2，防御性对股票也成立）；指数行产出后由 domain 投影剔除无意义字段（R1/R3 在投影层解决） |
| Background | `bootstrap`、`scheduler.ts`、`rpc-handlers.ts` | bootstrap 返回带指数行情；每轮刷新周期把指数并入 codes；Badge 逻辑不变（badge 仍只看自选股） |
| Popup | `components/index-strip.ts`（新）+ `store/reducer.ts` + `view-models.ts` | 顶部指数条 Light DOM 组件（可复用 quote-status 的红涨绿跌 token）；reducer 增加 `indexQuotes` 状态；组件只收 ViewModel 不碰 Store |
| 测试 | `tests/unit/infrastructure/` | parsers 用本次实证的真实响应做 fixture（含指数 pe=0、腾讯 limitUp=-1、北证50 87 字段的对抗样本）；红→绿验证 |
| | `tests/e2e/` | 指数条渲染 + 刷新 + 「指数字段永不出现 PE/涨跌停」断言；a11y 走查 |
| 商店素材 | `capture-store-assets.mjs` | 截图形态变化后重跑（若 UI 变化可见） |

估算：方案 A 约 1.5~2.5 天（含测试与 E2E）；方案 B 另加 2~3 天。

## 6. 验证计划（对齐验证纪律）

1. **实证 fixture**：parsers 单测的指数 fixture 直接取自本报告 §2 的真实响应
   （不是手写理想样本）——尤其 R1/R2 的哨兵值必须固化成对抗用例。
2. **断言会失败吗**：新增「指数不出现 PE/PB/涨跌停」的负向断言，确认在当前代码上先红后绿。
3. **门禁落位**：新测试文件放进会跑的 glob（`tests/unit/domain|protocol|infrastructure/`、
   `tests/component/`、`tests/e2e/`）；若新增 npm script 需同步 `ci.yml` / `release.yml`。
4. **test:live 冒烟**：指数代码加入 `test:live` 的清单，防止接口静默变更。
