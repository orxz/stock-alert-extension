# v1.3.0 架构与体验设计

- **状态：** 设计评审完成
- **日期：** 2026-08-01
- **目标版本：** v1.3.0
- **前置版本：** v1.2.1（可信基线）

## 1. 背景

v1.2.1 建立了可信基线：数据正确、行情降级、持久化安全、测试覆盖和确定性打包。但两个结构性问题保留到 v1.3.0：

1. **Popup 和 Background 各自创建 QuoteService 实例**，独立维护行情状态。两个上下文可能漂移：Popup 显示实时行情时 Badge 可能仍是缓存，反之亦然。
2. **popup.js 是 1329 行的单一 App 对象**，承担状态管理、行情请求、DOM 渲染、事件绑定、分组/股票 CRUD、搜索、拖拽、排序、列配置、Tooltip 和 Toast 等全部职责。可维护性差，新功能接入成本高。

此外，当前 UI 缺少系统性的无障碍设计：按钮依赖 `onclick` 而非键盘可达、颜色对比度未验证、无 ARIA 标记。

## 2. 目标与非目标

### 2.1 目标

- Service Worker 成为行情数据的唯一所有者，Popup 通过消息总线请求行情。
- Popup 不再直接创建 QuoteService，消除双实例漂移。
- popup.js 拆分为 5 个职责模块，每个模块可独立测试。
- 满足 WCAG 2.1 AA 基础合规：键盘导航、ARIA 标记、触控目标、颜色对比度。
- 提取共享格式化模块，消除 Popup 与 Background 之间的格式化代码重复。
- 保持运行时零依赖、无需构建。

### 2.2 非目标

- 不引入 TypeScript 编译或前端框架。
- 不实现价格阈值通知、提醒历史或静默时段（v1.4.0）。
- 不接入外部交易日历服务。
- 不重设计视觉风格（配色、布局、字体保持 v1.2.1 基线）。
- 不改变数据模型 schema（继续使用 v2）。

## 3. 架构：Service Worker 中心化

### 3.1 消息总线协议

Popup 和 Background 通过 `chrome.runtime.sendMessage` 通信，采用 RPC 模式：

**请求格式：**
```js
{ action: string, payload?: object }
```

**响应格式：**
```js
// 成功
{ ok: true, data: any }
// 失败
{ ok: false, error: { code: string, message: string } }
```

**Action 列表：**

| Action | Payload | 返回 data | 说明 |
|--------|---------|-----------|------|
| `quote:read` | `{ codes: string[] }` | `QuoteSnapshot` | 读取缓存，不触发网络 |
| `quote:refresh` | `{ codes: string[], force?: boolean }` | `QuoteSnapshot` | 读取+刷新，触发网络请求 |
| `storage:read` | `{}` | `{ groups, watchlist, boardConfig }` | 读取全部用户数据 |
| `storage:boardConfig` | `{ groupId }` | `BoardConfig` | 读取单个分组看板配置 |
| `storage:addStock` | `{ code, name, groupIds }` | `{ watchlist }` | 添加股票 |
| `storage:removeStocks` | `{ codes, groupId }` | `{ watchlist }` | 批量移除 |
| `storage:moveStocks` | `{ codes, fromGroup, toGroups }` | `{ watchlist }` | 批量移动 |
| `storage:togglePin` | `{ groupId, code }` | `{ watchlist }` | 切换置顶 |
| `storage:setManualOrder` | `{ groupId, orderMap }` | `{ watchlist }` | 设置手动排序 |
| `storage:createGroup` | `{ name }` | `{ groups }` | 新建分组 |
| `storage:renameGroup` | `{ groupId, name }` | `{ groups }` | 重命名分组 |
| `storage:deleteGroup` | `{ groupId }` | `{ groups, watchlist }` | 删除分组 |
| `storage:reorderGroups` | `{ ids }` | `{ groups }` | 重排分组 |
| `storage:saveBoardConfig` | `{ groupId, patch }` | `{}` | 保存看板配置 |

### 3.2 路由器

Background 新增 `router.js` 模块，负责：

1. 接收 `chrome.runtime.onMessage` 消息。
2. 校验 `action` 和 `payload` 格式。
3. 分发到对应处理函数。
4. 包装返回值为 `{ ok, data }` 或 `{ ok, error }` 格式。
5. 未知 action 返回 `{ ok: false, error: { code: 'UNKNOWN_ACTION', message } }`。

```js
// router.js 核心结构
const routes = {
  'quote:read': handleQuoteRead,
  'quote:refresh': handleQuoteRefresh,
  'storage:read': handleStorageRead,
  // ...
};

chrome.runtime.onMessage.addListener((request, sender, sendResponse) => {
  const handler = routes[request.action];
  if (!handler) {
    sendResponse({ ok: false, error: { code: 'UNKNOWN_ACTION', message: `Unknown action: ${request.action}` } });
    return false;
  }
  handler(request.payload)
    .then(data => sendResponse({ ok: true, data }))
    .catch(err => sendResponse({ ok: false, error: { code: err.code || 'INTERNAL', message: err.message } }));
  return true; // 保持消息通道开放（异步响应）
});
```

### 3.3 行情数据流

**v1.2.1（当前）：** Popup 和 Background 各自创建 QuoteService，独立请求行情。

```
Popup ──── QuoteService #1 ──── East Money / Sina
Background ── QuoteService #2 ──── East Money / Sina
```

**v1.3.0：** Background 独占 QuoteService，Popup 通过 RPC 请求。

```
Popup ──sendMessage──→ Background Router ──→ QuoteService ──→ East Money / Sina
                                              ↓
                                         chrome.storage.local
```

### 3.4 并发与单航程合并

Popup 可能多次快速请求相同代码集合（如切换分组、手动刷新）。Background 端的 QuoteService 已内置单航程（single-flight）合并：相同代码集合的进行中请求共享同一个 Promise。

v1.3.0 新增 read+refresh 轮询模式：

```js
// Popup 端：先读缓存快速渲染，再请求刷新
async function loadQuotes(codes) {
  // 1. 立即读取缓存（不触发网络）
  const cached = await bridge.send('quote:read', { codes });
  render(cached);
  // 2. 请求刷新（触发网络，返回更新后的快照）
  const refreshed = await bridge.send('quote:refresh', { codes });
  render(refreshed);
}
```

### 3.5 定时刷新迁移

Popup 的定时刷新（`scheduleNextRefresh`）改为向 Background 发送 `quote:refresh` 消息。Background 已有 `chrome.alarms` 定时器继续独立运行，更新 Badge。

如果 Popup 和 Background 的刷新恰好同时发生，QuoteService 的单航程机制确保只发一次网络请求。

### 3.6 MV3 Service Worker 生命周期

Manifest V3 的 Service Worker 会被 Chrome 在空闲时挂起（通常 30 秒无活动后）。v1.3.0 需要处理以下边界情况：

**SW 被挂起时 Popup 发送消息：**
Chrome 会自动唤醒 SW 来处理 `chrome.runtime.onMessage`。`QuoteService` 实例会重新创建，缓存从 `chrome.storage.local` 恢复。Popup 不感知 SW 重启——`bridge.send` 会等到 SW 响应。

**SW 重启后 QuoteService 状态丢失：**
QuoteService 的内存状态（进行中请求、退避计时器、generation 计数器）在 SW 重启后丢失。影响：
- 退避计时器重置：如果刷新连续失败触发退避，SW 重启后退避被重置。可接受——退避是优化，不是正确性保证。
- generation 计数器重置：从 0 开始。Popup 端保存自己的 generation，当收到 SW 返回的较小 generation 时，应用"不小于"规则会拒绝过旧结果。修复：SW 重启后 generation 从当前时间戳派生，而非从 0 开始。

**Bridge 超时保护：**
```js
const SW_TIMEOUT_MS = 10000;

async send(action, payload) {
  const timer = new Promise((_, reject) =>
    setTimeout(() => reject(new Error('SW_TIMEOUT')), SW_TIMEOUT_MS)
  );
  try {
    const response = await Promise.race([
      chrome.runtime.sendMessage({ action, payload }),
      timer
    ]);
    // ...处理响应
  } catch (e) {
    if (e.message === 'SW_TIMEOUT') {
      throw new Error('后台服务未响应，请重试');
    }
    throw e;
  }
}
```

## 4. Popup 模块拆分

### 4.1 结构概览

```
popup.html
  ├─ popup.js          (入口，~50 行)
  ├─ popup-bridge.js   (RPC 客户端)
  ├─ popup-state.js    (状态管理)
  ├─ popup-render.js   (DOM 渲染)
  └─ popup-actions.js  (用户操作)
```

### 4.2 `popup-bridge.js` — RPC 客户端

职责：
- 封装 `chrome.runtime.sendMessage` 为 Promise 接口。
- 提供 `send(action, payload)` 方法，返回 `Promise<data>`。
- 失败时抛出包含 `code` 和 `message` 的错误。
- 内置超时保护（10 秒），防止 Service Worker 未响应时 Popup 挂起。

```js
const Bridge = {
  async send(action, payload) {
    const response = await chrome.runtime.sendMessage({ action, payload });
    if (!response) throw new Error('SW_NO_RESPONSE');
    if (!response.ok) throw Object.assign(new Error(response.error.message), { code: response.error.code });
    return response.data;
  }
};
```

### 4.3 `popup-state.js` — 状态管理

职责：
- 持有 Popup 视图状态（当前分组、视图模式、排序、搜索、批量模式等）。
- 从 Bridge 加载初始数据和行情。
- 提供订阅接口，状态变更时通知渲染模块。

```js
const State = {
  current: { /* 视图状态 */ },
  listeners: new Set(),

  subscribe(fn) { this.listeners.add(fn); return () => this.listeners.delete(fn); },
  notify() { this.listeners.forEach(fn => fn(this.current)); },

  async init() {
    const data = await Bridge.send('storage:read', {});
    Object.assign(this.current, data);
    const snapshot = await Bridge.send('quote:read', { codes: data.watchlist.map(s => s.code) });
    this.current.quoteSnapshot = snapshot;
    this.notify();
  }
};
```

### 4.4 `popup-render.js` — DOM 渲染

职责：
- 订阅 State 变更，增量更新 DOM。
- 包含分组 Tab、工具栏、网格视图、列表视图、空状态、状态栏的渲染函数。
- 行情浮窗（tooltip）的显示和隐藏。
- Toast 和确认弹层。
- HTML 转义（`esc`）。

从当前 popup.js 迁移的函数：
- `renderGroupTabs`, `renderBoard`, `renderGrid`, `renderList`
- `showQuoteTooltip`, `hideQuoteTooltip`
- `toast`, `_confirm`
- `formatVolume`, `formatAmount`
- `updateQuoteStatus`, `updateTimeLabel`
- `renderColPanel`

### 4.5 `popup-actions.js` — 用户操作

职责：
- 分组/股票 CRUD（通过 Bridge 发送 RPC）。
- 排序、拖拽、列配置、搜索、批量选择。
- 手动刷新、价格隐藏切换。
- 操作期间禁用/启用按钮。
- 操作后更新 State 并触发重新渲染。

从当前 popup.js 迁移的函数：
- `submitAddStock`, `_submitAddStock`, `openAddModal`
- `submitMove`, `_submitMove`, `openMoveModal`
- `submitGroupModal`, `deleteGroup`, `openGroupModal`
- `removeStocks`, `_removeStocks`
- `togglePin`, `_togglePin`, `manualReorder`
- `switchGroup`, `switchView`, `onSortSelectChange`, `sortByField`
- `toggleSelect`, `toggleBatchMode`, `onSearch`
- `togglePriceHidden`, `toggleColumn`, `reorderColumns`
- `manualRefresh`, `refreshQuotes`, `scheduleNextRefresh`

### 4.6 `popup.js` — 入口

职责：
- 按正确顺序加载模块。
- DOMContentLoaded 时初始化 State 和绑定 Actions。
- 清理定时器。

```js
// popup.js (~50 行)
async function init() {
  await State.init();
  Actions.bind(State, Render);
  Render.subscribe(State);
  Render.render(State.current);
  await Actions.refreshQuotes();
  Actions.scheduleNextRefresh();
}

document.addEventListener('DOMContentLoaded', init);
window.addEventListener('beforeunload', () => Actions.cleanup());
```

### 4.7 模块加载顺序

Manifest V3 使用全局脚本加载（无 ES modules），通过 `popup.html` 中的 `<script>` 标签顺序控制：

```html
<script src="popup-bridge.js"></script>
<script src="popup-state.js"></script>
<script src="popup-render.js"></script>
<script src="popup-actions.js"></script>
<script src="popup.js"></script>
```

每个模块挂在全局对象上（`window.Bridge`, `window.State`, `window.Render`, `window.Actions`），`popup.js` 组合它们。

## 6. 无障碍合规 (WCAG 2.1 AA)

### 6.1 键盘导航

### 6.3 触控目标

所有可点击元素的最小触控区域为 44×44px（WCAG 2.5.5 Target Size）。

当前问题：
- `header-btn`（＋/✎/👁）实际尺寸约 28×28px。通过 `padding` 扩展触控区域到 44px，视觉尺寸不变。
- `view-btn`（▦/☰/⚙）同理。
- `tab-add`（＋）同理。
- 排序箭头和列拖拽手柄不满足触控目标要求，但属于辅助操作，标注 `aria-hidden` 并提供替代路径（菜单或键盘）。

### 6.4 颜色对比度

WCAG AA 要求：
- 正常文本：对比度 ≥ 4.5:1
- 大文本（18pt+ 或 14pt+ 粗体）：对比度 ≥ 3:1
- 非文本 UI 组件：对比度 ≥ 3:1

需验证的颜色对：
| 前景 | 背景 | 当前对比度 | 状态 |
|------|------|-----------|------|
| `#2C3E50`（主文本） | `#FFFFFF` | ~10:1 | 达标 |
| `#8A93A6`（次要文本） | `#FFFFFF` | ~3.5:1 | 不达标，需加深到 `#6B7280`（~5:1） |

### 6.5 屏幕阅读器

- 股票卡片读出：名称 + 价格 + 涨跌幅 + 状态（实时/缓存/缺失）。
- 空状态读出："当前分组暂无自选股，按按钮添加"。
- Toast 消息读出后清除。
- 图标按钮（＋/✎/👁/▦/☰/⚙）使用 `aria-label` 描述用途。
- 装饰性图标（📌）使用 `aria-hidden="true"`。

### 6.6 减弱动效偏好

尊重用户的 `prefers-reduced-motion` 系统设置：

```css
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    animation-duration: 0.01ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: 0.01ms !important;
  }
}
```

影响：
- 刷新按钮的旋转动画变为静态加载指示（如 `aria-busy="true"`）。
- 骨架屏的脉动效果关闭，变为静态灰色占位。
- 卡片 hover 缩放（`transform: scale(.92)`）变为仅颜色变化。

### 6.7 浏览器缩放

Popup 在 Chrome 扩展环境中跟随浏览器缩放。验证范围：90%–150%。

- 90%：确认 Popup 不会出现多余空白或滚动条。
- 125%：确认 420px 宽度下的网格卡片仍可读（每行 3 张 → 可能变 2 张）。
- 150%：确认文本不溢出、按钮不重叠。卡片内容允许截断（`text-overflow: ellipsis`）。

## 10. 迁移策略

### 10.1 分支策略

`feature/v1.3.0-architecture` 分支，分 5 个阶段提交：

1. 提取 `quote-format.js`（纯重构，无行为变化）
2. 新增 `router.js` + Background 接入消息总线
3. 新增 `popup-bridge.js` + Popup 接入 RPC
4. 拆分 `popup.js` → 4 模块 + 入口
5. a11y 改进（ARIA、键盘、对比度、触控目标）

每个阶段独立通过全部测试。

### 10.2 回退策略

每个阶段是一个完整的提交。如果某个阶段引入回归，可以 `git revert` 该提交而不影响其他阶段。

阶段 3（Popup 接入 RPC）是风险最高点：如果消息总线不稳定，可以回退到阶段 2 并让 Popup 继续直接使用 QuoteService。

## 11. 不在范围

- 价格阈值通知、提醒历史、静默时段（v1.4.0）
- 交易日历服务集成（v1.4.0+）
- TypeScript 编译或 ES module 运行时
- 视觉重设计（配色、字体、间距保持 v1.2.1）
- 新增分组类型（如智能分组、行业分组）
- 多窗口/多 Popup 同步
