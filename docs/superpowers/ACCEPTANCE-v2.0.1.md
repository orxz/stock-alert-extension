## 二、审查方法

- 对行情字段链路做**实网核对**：用与代码完全相同的 URL 参数请求两个数据源，
  逐字段与已知真值比对，而不是相信 fixture；
- 对可疑点先写**失败的**回归测试，红→绿验证后再定论；
- 对几何类声明（列宽 / 不溢出）用真实扩展实测，不采信截图与描述；
- 对每条 CHANGELOG 声明回查代码，声明与实现不符即记为文档缺陷。

## 三、发现并修复的产品缺陷

### 3.1 P1 — 东财 f51/f52 不是涨停价/跌停价，详情面板显示天文数字

**证据（2026-08-06 实网）。** 用代码同款参数请求 `ulist.np/get?fltt=2`：

| 股票 | 现价 | 昨收 | f51 | f52 |
|------|------|------|-----|-----|
| sh600519 贵州茅台 | 1308.55 | 1306.45 | **271524528742.4** | **22132684069.8** |
| sz000001 平安银行 | 11.27 | 11.25 | **0.0** | 10879000000.0 |

同一时刻腾讯源 `[47]`/`[48]` 给出真值 **1437.10 / 1175.81**（= 1306.45×1.1 / ×0.9，
与 A 股 ±10% 涨跌停一致）；东财 **逐只** 接口 `stock/get` 上 f51/f52 也确为
`143710 / 117581`。

**根因。** f51/f52 的含义**随 endpoint 变化**：只有 `stock/get` 上是涨跌停价，
本项目用的批量接口 `ulist.np/get` 上这两个槽位装的是别的量纲。设计文档照搬了
`stock/get` 的字段表。

**用户可见后果。** `formatDetailPrice` 直接 `toFixed(2)`——悬停详情面板的
「涨停价」会渲染成 `271524528742.40`，平安银行渲染成 `0.00`。

**为什么门禁没抓到。** 单测 fixture 手写 `f51: 1650, f52: 1350`（对 1500 元的价格
恰好像涨跌停），再断言它们映射为 limitUp/limitDown。**mock 把错误假设固化成了
被测事实，任何 mock 测试都不可能证伪它**——与 v2.0.0 那条恒真断言同源。

**修复。** 已从东财请求字段与解析中移除 f51/f52。对该 endpoint 做 **f1–f300 全量扫描，
无任何字段返回真实涨跌停**；改用逐只 `stock/get` 会让 500 只自选股从 1 次请求变成
500 次，不可接受。故主源该两项按既有缺失约定显示 `--`，腾讯源正常显示真值。
回归测试直接用实网观测值构造，并在注释中留存出处。

### 3.2 P2 — 对账路径漏掉「选中集 ⊆ 可见集」不变量

`mutation/confirmed` 会把已移出/删除的选中项剔除，但 `bootstrap/confirmed` 只做了
分组回退、没做选中集收敛。而写命令超时进入 uncertain 后，`doReconcile` 正是通过
`app:bootstrap` 装载权威快照——**批量删除超时的场景恰好只走这条没收敛的路径**：
股票已从列表消失，批量工具栏仍为它们计数（`selectBatchToolbar` 直接用
`state.view.selectedCodes.length`）。

修复：抽出 `settleView`，两条替换 userData 的路径共用同一套不变量收敛；
`g_all` 语义由 `stocksForGroup` 处理，已验证不会误清空。

## 四、门禁与契约缺口（本轮一并修复）

### 4.1 4 个测试文件不被任何门禁执行

`tests/unit/build/*.test.mjs`（architecture-gates / build-extension / capacity-fixture /
release-allowlist，共 19 条断言）从未运行：`test:unit` 的 glob 只匹配 `*.test.ts`，
`test:capacity` 只覆盖其中 1 个且无人调用，`ci` 与 `release:verify` 都不包含它们。
这与 v2.0.0 那次「a11y 门禁从未在 CI 跑过」是同一类问题。

修复：新增 `test:build` 脚本并接入 `ci`。**接上电就立刻烧出两个真问题**——
说明这批测试不是「一直在默默守护」，而是早已与现实脱节：

1. `build-extension.test.mjs` 把期望版本写死成 `'2.0.0'`。版本升到 2.0.1 时它以
   「测试失败」的形式表现，掩盖了真正该断言的东西：**构建产物的版本必须与源
   `extension/manifest.json` 一致（构建不得篡改版本）**。已改为从唯一真相读取。
2. `release-allowlist.test.mjs` 的前置条件是「已打包」（`dist/*.zip` 存在），而
   `ci` 根本不打包——放进 `ci` 必然失败。已移到 `tests/release/`，新增
   `test:release` 并接在 `release:verify` 的 `package:extension` 之后。
   **用目录区分前置条件**，两个 glob 各归各的门禁，新增文件不会再落进跑不起来的那一档。

最终：`test:build` 17 条进 `ci`，`test:release` 2 条进 `release:verify`，均通过。

### 4.2 控件改名会让 WCAG 尺寸断言静默失效

a11y 用例对次级控件做 24px 下限检查时写的是
`if ((await el.count()) === 0) continue;`——**选择器落空就跳过**。
本轮把「多选」的 `data-action` 改名为 `manage-holdings` 时，若忘了同步这份名单，
该控件会悄悄退出检查而门禁全绿。已改为落空即抛错（`boundingBox` 为空同理）。

### 4.3 行高契约的守卫是单向的

`TABLE_ROW_EXTENT` 与 `--row-h` 曾漂移到 48 vs 40，每行错位 8px。现有 E2E 只把 CSS
与字面量 `'40px'` 比对——**CSS 漂移能抓到，TS 常量漂移抓不到**。
修复：新增组件测试直接比对两个真实来源（读 tokens.css × 导入常量），
已红绿验证（把 CSS 改成 44px 时确实失败）。

## 七、遗留与后续

1. **涨停/跌停实际只有腾讯源提供**。东财是主源，多数情况下这两项显示 `--`。
   要让它们常驻有真值，只能加请求（逐只 `stock/get`）或按板块比例推算——后者对
   ST（5%）会算错，等于用另一种方式显示错误数据。建议保持现状。
2. **主源当前从本机不可达**：`push2.eastmoney.com/api/qt/ulist.np/get` 连续 5 次返回
   502（curl 与 node fetch 一致），而 `push2delay` 与腾讯均 200。实网烟测仍 3.7s 通过，
   即**降级链路在真实条件下承接住了**。但该域名 DNS 解析到 `198.18.2.126`（常见于本机
   VPN/代理接管），**不能据此断定东财对所有用户不可达**，需在干净网络复核。
3. ~~版本号未提升~~ **已收尾**：`package.json` 与 `manifest.json` 已提升到 2.0.1，
   CHANGELOG 去掉 Unreleased 标记。
4. **悬停详情翻转不随滚动重算**：`refreshTooltipFlip` 以 `lastHoveredRow` 短路，且无
   scroll 监听。指针停住不动、仅滚动列表时，翻转结论不会更新（代码事实；实际可见
   程度未实测）。属体验边角，非正确性问题。
5. ~~`scripts/tmp-list.png` 调试截图~~ **已删除**（1280×720，无任何引用，内容是旧版界面）。
6. v2.0.0 遗留项仍然有效：GitHub CI 比本地 `ci` 薄（未跑 component / a11y / build）；
   实网用例不进门禁；薄适配器无单测。

## 八、命名收敛：「多选」→「管理持仓」

「多选」描述的是**交互手段**（能勾选多行），不是用户来这里要办的事。该模式的出口是
全选 / 移动到分组 / 移除——成批管理自选持仓。已按「叫它做的事」统一命名：

| 位置 | 旧 | 新 |
|------|----|----|
| 入口按钮可见文案 / `aria-label` | 多选 | **管理持仓** |
| 入口按钮 `data-action` | `multiselect` | `manage-holdings` |
| 批量工具栏 `aria-label` | 批量操作 | **持仓管理** |
| 工具栏取消按钮 `aria-label` | 取消多选模式 | **退出持仓管理** |

读屏用户从入口到工具栏听到的是同一个词。新增组件测试同时锁死可见文案与
`aria-label`，避免只改一处、读屏仍念旧名。

**未改的部分及理由**：`selectionMode` / `selection-mode-change` / `selectedCodes`
描述的是**机制**（选择态），本身准确，且被 table / board / store / toolbar 广泛引用——
改名有大范围回归风险而无用户可见收益。命名边界定在「功能叫什么」而非「机制叫什么」。

**布局验证**（4 字比 2 字宽约 24px，而代码注释记录过「6 个分组就把右侧按钮挤出可视区」）：
420px 下实测 1/3/5/7 个自定义分组，按钮恒为 78×28、位置固定（left=334, right=412），
标签栏内部滚动吸收压力（8 分组时 scrollWidth 423 > clientWidth 257），文档无横向溢出。

## 九、结论

**通过。**

本轮修复 1 个 P1（详情面板显示天文数字）、1 个 P2（对账后选中集不收敛）、
3 个门禁缺口（19 条断言从不执行、控件改名致 WCAG 断言静默失效、行高契约单向守卫）、
2 处文档失真，并完成「多选」→「管理持仓」的命名收敛与版本收尾（2.0.1）。

值得记录的一点：全部门禁在修复前就是绿的。抓到 P1 的不是任何一条断言，而是
**拿真实接口的返回值去核对 fixture 里的假设**。v2.0.0 的教训是「恒真断言掩盖了
功能失效」，这一轮是「mock 把错误假设固化成了事实」——两者的解药是同一个：
凡是跨越进程/网络边界的契约，都必须有一次实证，而不是只有一份 mock。
