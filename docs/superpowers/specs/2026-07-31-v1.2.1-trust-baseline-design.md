# v1.2.1 可信基线设计

- **状态：** 已批准
- **日期：** 2026-07-31
- **目标版本：** v1.2.1

## 1. 背景

股票提醒助手 v1.2.0 已具备多分组看板、双行情源、排序、置顶和后台 Badge，但当前实现存在会损害用户信任的问题：

- 从普通分组添加的股票可能不出现在「全部」分组和后台 Badge 中。
- 两个行情源失败时会生成随机演示行情，后台 Badge 无法说明这些数字不是真实行情。
- 主行情源部分成功时，缺失股票不会继续走备用源；Popup 会把缺失价格显示为 `0.00`。
- Popup 和 Background 分别维护行情状态与排序逻辑，结果容易漂移。
- 看板配置依赖防抖和 `beforeunload` 异步写入，关闭 Popup 或快速操作时可能丢失。
- 隐私政策声称不会向第三方发送任何用户数据，但行情查询会发送所查询的股票代码。
- 项目没有自动化测试、CI 和可验证的发布打包流程。

v1.2.1 的任务是建立可信、可测试的稳定性基线，不进行完整架构迁移或主要界面重设计。

## 2. 范围分解

完整优化拆成三个连续版本：

1. **v1.2.1 可信基线：** 数据正确性、行情降级、持久化安全、隐私文案、测试和发布门禁。
2. **v1.3.0 架构与体验：** 拆分 `popup.js`、Service Worker 中心化行情缓存、无障碍和交互重构。
3. **v1.4.0 真正的提醒：** 价格/涨跌幅规则、通知、静默时段和提醒历史。

本文只定义 v1.2.1。

## 3. 目标与非目标

### 3.1 目标

- 「全部」始终展示整个自选列表，后台 Badge 不漏股票。
- 生产环境只展示真实行情、7 天内缓存或 `--`，绝不生成随机价格。
- 东方财富与新浪按股票粒度合并，部分失败不影响成功股票。
- Popup 和 Background 使用同一套行情状态和排序语义。
- 现有用户数据自动、幂等、可恢复地升级。
- 所有用户配置写入串行化，不依赖页面卸载完成异步保存。
- 行情失败时立即展示可理解的缓存状态，且不清空最后一次有效数据。
- 运行时继续零依赖、无需构建；允许开发依赖用于检查、测试和打包。
- Pull Request 必须通过静态检查、单元测试、覆盖率和扩展端到端冒烟测试。

### 3.2 非目标

- 不在 v1.2.1 建立 Popup 与 Background 的消息总线。
- 不让 Service Worker 成为唯一行情所有者。
- 不大规模拆分 `popup.js`。
- 不引入 TypeScript 编译产物或前端框架。
- 不实现价格阈值通知、提醒历史或静默时段。
- 不接入外部交易日历服务。

## 4. 架构

v1.2.1 保持 Manifest V3 和全局脚本加载方式，新增两个可独立测试的小模块。

### 4.1 `quotes.js`

职责仅限：

- 东方财富搜索与行情请求。
- 新浪行情请求。
- 响应解析。
- 行情字段标准化。

`quotes.js` 不再决定 Demo 降级、缓存、过期状态或用户提示。生产路径删除随机演示行情。

### 4.2 `quote-service.js`

统一负责：

- 4 秒请求超时。
- 每批最多 50 只股票。
- 东方财富优先、仅对缺失股票请求新浪。
- 按股票生成 `fresh`、`cached`、`missing` 状态。
- 7 天本地缓存。
- 单次请求复用、旧请求丢弃和失败退避。
- 汇总实时、缓存和缺失数量。

### 4.3 `stock-utils.js`

提供 Popup 与 Background 共用的纯函数：

- `getStocksForGroup(watchlist, groupId)`
- `sortStocks(stocks, quoteResults, groupId, sortField, sortDirection)`
- `countStocksForGroup(watchlist, groupId)`
- `normalizeStockCode(code)`

「全部」由这些函数计算，不通过 `groupIds.includes('g_all')` 判断。

### 4.4 `storage.js`

继续管理用户配置，并增加：

- `schemaVersion: 2`
- v1 到 v2 的幂等迁移
- 数据清洗与一次性迁移备份
- 串行用户配置写入
- 按股票代码分键的行情缓存 API

### 4.5 `popup.js`

只消费规范化的行情结果，负责：

- 立即渲染本地缓存。
- 发起到期刷新。
- 展示实时、缓存、缺失三种状态。
- 展示整体状态摘要和单股过期标记。
- 使用串行 Storage API 保存配置。
- 在异步用户操作期间禁用对应按钮。

### 4.6 `background.js`

使用相同的 `QuoteService` 和 `StockUtils`：

- 实时行情使用红绿 Badge。
- 缓存行情保留数字但使用灰色 Badge。
- 无数据使用灰色 `--`。
- Tooltip 标注缓存状态和行情时间。

完整的后台中心化保留到 v1.3.0。

## 5. 数据模型

### 5.1 用户配置

顶层键：

- `schemaVersion`
- `groups`
- `watchlist`
- `boardConfig`
- `migrationBackup:v1.2.1`

`watchlist[].groupIds` 在 v2 中只保存普通分组 ID。空数组表示股票只存在于全局自选列表，但仍会出现在「全部」视图中。`manualOrder.g_all` 和 `pinned.g_all` 继续用于「全部」视图的排序与置顶。

### 5.2 行情缓存

每只股票使用独立键：

```text
quoteCache:sh600519
quoteCache:sz000001
```

值结构：

```js
{
  cacheVersion: 1,
  code: 'sh600519',
  provider: 'eastmoney',
  fetchedAt: 1785477600000,
  quote: {
    name: '贵州茅台',
    price: 1689,
    prevClose: 1675.5,
    open: 1678,
    high: 1698,
    low: 1670,
    volume: 123456,
    amount: 208765432,
    change: 13.5,
    changePercent: 0.81
  }
}
```

缓存超过 `7 * 24 * 60 * 60 * 1000` 毫秒后不再用于展示，并在读取或删除股票时清理。缓存损坏只影响对应股票，不影响自选列表。

### 5.3 行情服务结果

每只股票的结果结构：

```js
{
  code: 'sh600519',
  status: 'fresh', // fresh | cached | missing
  source: 'eastmoney', // eastmoney | sina | cache | none
  fetchedAt: 1785477600000,
  quote: { /* 标准化行情，missing 时为 null */ },
  error: null // timeout | http | parse | unavailable | null
}
```

汇总结构：

```js
{
  generation: 12,
  results: { sh600519: quoteResult },
  counts: { fresh: 1, cached: 0, missing: 0 },
  attemptedAt: 1785477600000,
  succeededAt: 1785477600000
}
```

`generation` 为当前上下文内递增的刷新序号。Popup 和 Background 只能应用不小于当前已应用序号的结果，防止较旧请求覆盖较新状态。

## 6. 行情数据流

### 6.1 Popup

1. 从 Storage 读取用户数据和对应股票缓存。
2. 立即渲染缓存。缓存年龄在当前刷新间隔内且其后没有失败记录时可显示为实时；其他 7 天内缓存显示为过期。
3. 根据市场时段和最近请求时间决定是否联网。
4. 东方财富按 50 只分批查询，每批超时 4 秒。
5. 仅将东方财富未返回的代码交给新浪。
6. 合并每只股票的结果，成功项更新独立缓存。
7. 失败项回退到 7 天内缓存；无缓存或缓存过期则返回 `missing`。
8. 只有真实网络成功才更新“最近成功时间”。

### 6.2 Background

Background 使用相同流程，但只请求生成当前 Badge 和 Tooltip 所需的股票；行情字段排序时仍需获取该视图的完整股票行情。缓存新鲜时不重复请求。

### 6.3 并发与退避

- 同一上下文中，相同代码集合的进行中请求复用同一个 Promise。
- 每次刷新分配递增序号，较旧请求完成后不得覆盖较新状态。
- 自动请求连续失败时按 30 秒、2 分钟、5 分钟退避，最大 5 分钟。
- 手动刷新可以绕过一次退避，但仍有单次进行中请求保护。
- 部分成功重置成功股票的失败状态，不清空其他股票的缓存。

## 7. 刷新策略

所有市场时间使用 `Asia/Shanghai`：

- 工作日 09:15–11:35、12:55–15:05：
  - Popup 每 10 秒。
  - Background 每 30 秒。
- 其他时间：
  - Popup 和 Background 每 5 分钟。
- 手动刷新始终立即尝试。
- v1.2.1 不使用交易日历，因此法定休市日仍按工作日时间窗处理。

## 8. 用户可见状态

### 8.1 Popup 状态栏

示例：

- `实时 8 · 缓存 2`
- `缓存 10 · 行情服务暂不可用`
- `无行情数据 · 点击刷新重试`

缓存股票的价格旁显示“旧”标记及行情时间。完全缺失显示 `--`，绝不显示 `0.00`。

系统分别保存：

- 最近请求时间
- 最近真实成功时间

读取缓存或失败不得显示“刚刚更新”。

### 8.2 Badge 和 Tooltip

- `fresh`：保持红涨绿跌。
- `cached`：显示缓存涨跌幅，背景灰色；Tooltip 加“行情已过期”和时间。
- `missing`：显示灰色 `--`；Tooltip 显示“暂无行情”。

## 9. 「全部」分组语义

- `getStocksForGroup(watchlist, 'g_all')` 返回整个 `watchlist`。
- 普通分组只匹配 `groupIds`。
- 「全部」数量等于 `watchlist.length`。
- 从「全部」移除股票会全局删除该股票。
- 从普通分组移除只删除该分组 ID，允许 `groupIds` 变为空数组。
- 移动到「全部」不写入成员标记；股票天然已经属于「全部」。
- 旧数据中的 `g_all` 成员标记在迁移时删除，但 `manualOrder.g_all`、`pinned.g_all` 和 `boardConfig.g_all` 保留。

## 10. 存储迁移与写入

当 `schemaVersion` 小于 2 时：

1. 将原始 `groups`、`watchlist`、`boardConfig` 和 `watchlist_legacy` 保存到 `migrationBackup:v1.2.1`。
2. 确保默认分组存在并固定首位。
3. 规范股票代码。
4. 按代码合并重复股票，合并普通分组、置顶和手动排序信息。
5. 删除 `groupIds` 中的 `g_all` 和不存在的普通分组。
6. 修复字段缺失和无效看板配置。
7. 写入完整 v2 数据和 `schemaVersion: 2`。

再次运行迁移必须得到相同结果，不重复覆盖备份。

用户配置修改进入模块级 Promise 队列。每个修改在前一个修改完成后读取最新数据、应用纯函数并写回。看板设置在离散交互完成后立即排队保存，不使用 200 毫秒防抖，也不依赖 `beforeunload`。

## 11. 错误处理

- HTTP、超时和解析错误转换为稳定的内部错误码。
- 用户界面只显示可操作信息，不展示内部响应内容。
- Popup 初始化失败时仍渲染空状态和恢复提示，不白屏。
- 单只缓存损坏只删除该缓存键。
- 用户数据迁移失败时保留原数据和备份，不写入 `schemaVersion: 2`。
- 添加、移动、删除、置顶和分组操作期间禁用对应入口，完成或失败后恢复。
- 不在日志中输出完整自选股代码列表。

## 12. 隐私

隐私政策必须明确：

- 自选股和配置保存在本地，不由开发者收集。
- 查询行情时，所查询的股票代码会发送给东方财富或新浪。
- 第三方可能处理 IP、User-Agent 等正常网络信息。
- 扩展不使用远程代码，不增加主机权限或分析服务。
- 不上传遥测数据。

## 13. 测试与 CI

### 13.1 静态检查

- 所有 JavaScript 语法检查。
- JSDoc + TypeScript `checkJs`。
- ESLint 检查 Promise、全局变量和 DOM 使用。
- Manifest 入口、权限、版本和文件存在性校验。

### 13.2 单元测试

覆盖：

- 「全部」计算视图、普通分组和全局删除。
- 东方财富部分成功后只补查缺失股票。
- 超时、分批、请求复用和旧请求丢弃。
- 7 天缓存边界、损坏缓存和状态汇总。
- 缺失行情排序到末尾。
- 迁移幂等、重复股票合并和串行写入。
- 缓存 Badge 状态格式化。

稳定性模块要求至少 90% 行覆盖率和 85% 分支覆盖率。

### 13.3 端到端测试

Playwright 加载真实扩展，使用预置缓存和离线模式，不依赖真实外部行情：

- 在普通分组添加股票后，「全部」立即可见。
- 部分缓存显示整体摘要和单股过期标记。
- 缓存 Badge 为灰色，Tooltip 包含更新时间。
- 双击添加或快速切换设置不会丢数据。
- 损坏缓存不会白屏。
- 手动刷新失败后保留缓存。

### 13.4 CI

每个 Pull Request 必须通过：

- 静态检查
- 单元测试
- 覆盖率门槛
- Chrome 扩展端到端冒烟测试
- 发布包校验

## 14. 发布

- 版本升级为 `1.2.1`。
- Popup 版本从 `chrome.runtime.getManifest().version` 读取。
- 添加 MIT `LICENSE`。
- 更新 README、CHANGELOG、架构文档、模块文档、功能说明书和隐私政策。
- 商店截图必须来自真实 v1.2.1 扩展，不能继续显示 `v3.9`。
- 发布脚本只打包 Manifest 声明的运行文件，验证 ZIP 内容并输出 SHA-256。

## 15. 验收标准

满足以下全部条件才可发布：

1. 普通分组新增股票始终出现在「全部」和后台候选列表中。
2. 生产代码无法生成随机行情。
3. 任一数据源部分失败时，成功股票保留，缺失股票走备用源或缓存。
4. 7 天内缓存明确标为过期；超过 7 天显示 `--`。
5. 缓存 Badge 为灰色且 Tooltip 包含时间。
6. 快速连续配置操作不会丢失最后一次状态。
7. v1.2.0 用户数据自动迁移且迁移重复运行结果一致。
8. 隐私文案与实际股票代码请求一致。
9. 静态检查、单元测试、覆盖率、E2E 和发布包校验全部通过。
10. v1.2.1 ZIP 与源码、Manifest 和商店截图一致。
